# NodeTest32

Тестер нод VPN от [Manual32](https://manual32.online). Два скрипта дают короткий вердикт по серверу: годен ли он под ноду и реально ли через него ходит трафик. Без установки, зависимость по сути одна — `curl`.

Тестер отвечает не на «пингуется ли порт», а на то, что важно на самом деле: жив ли сервер, не оверселлен ли он, держит ли канал, не засвечен ли IP и **идёт ли трафик до выхода в интернет**. Панель может рисовать ноду зелёной, а через неё ничего не работать — это ловит только сквозной тест.

## Два инструмента

**`node-check.sh`** — снаружи внутрь. Запускаешь с чистого компа или соседнего VPS, скармливаешь ссылку из подписки, скрипт поднимает `xray` из неё и гонит настоящий трафик через ноду. Проверяет: хост и порт, латентность серией, маршрут, MTU-чёрную-дыру, маскировку, e2e через туннель (выходной IP, доступность сайтов, TTFB), скорость относительно твоего канала, паспорт IP (гео/ASN/репутация).

**`node-inside.sh`** — изнутри. Запускаешь на самой ноде по SSH. Проверяет то, что снаружи не видно: тип виртуализации (KVM или контейнер), оверселл по steal time, AES-NI, память/диск/swap, BBR, исходящий IPv6, фаервол, синхронизацию времени. Гоняй в первый час аренды свежего VPS — пока действует возврат.

Один смотрит, **работает ли сервис**, второй — **годен ли сам сервер**.

## Быстрый старт

```bash
git clone https://github.com/bini69-oi/NodeTest32.git
cd NodeTest32
```

Проверить ноду насквозь (ссылку возьми из подписки тест-юзера, в одинарных кавычках):

```bash
./node-check.sh 'vless://uuid@host:443?type=tcp&security=reality&pbk=...&sni=...#my-node'
```

Без ссылки — усечённо (хост, канал, маскировка, паспорт IP):

```bash
./node-check.sh 1.2.3.4 443
```

Проверить сам сервер изнутри (на ноде или по SSH):

```bash
ssh root@1.2.3.4 'bash -s' < node-inside.sh
```

## Где запускать `node-check.sh`

**Не с самой ноды** — скрипт это ловит и останавливается: сервер часто не достукивается до своего же публичного IP (hairpin), а localhost завышает скорость.

**С чистой машины, без включённых VPN.** Если на компе подняты другие туннели (на macOS это `utun0..N`), они перехватывают исходящие соединения и тест врёт — покажет провал на исправной ноде. Скрипт предупредит, но лучше просто выключить все VPN перед запуском.

Хочешь цифры «как у клиента из России» (вместе с работой ТСПУ) — запускай с домашнего РФ-канала. Хочешь чистые цифры самой ноды — с соседнего зарубежного VPS.

## Как взять ссылку для теста

Не бери ссылку своего боевого клиента — сожжёшь ему лимит устройств (HWID). Заведи в панели отдельного тест-юзера в изолированном скваде, возьми его ссылку из карточки хоста или подписки, прогони тест, потом удали юзера. `flow` и `path` копируй из ссылки байт-в-байт: угаданный `flow` даёт рукопожатие без трафика, а лишний или недостающий слэш в `path` у XHTTP роняет соединение в 404.

## Что значит вердикт

Каждая стадия печатает `✓` / `!` / `✗`, в конце сводная таблица и общий вывод. Возвращаемый код: `0` всё чисто, `1` есть предупреждения, `2` есть провалы — скрипт можно вставлять в свои проверки.

`!` (WARN) — работать будет, но с оговоркой (высокий пинг, MTU меньше 1500, засвеченный IP, нет swap). `✗` (FAIL) — до боя чинить: порт закрыт, трафик не идёт, маскировка палится, OpenVZ вместо KVM. На каждый не-`OK` в таблице есть строка «куда смотреть».

## Чем отличается от YABS / bench.sh

Те меряют железо и рисуют сырые цифры — а дальше думай сам. NodeTest32 даёт **вердикт по слоям** (где именно ломается: IP, маршрут, TCP, TLS, конфиг) и главное — **проверяет реальный трафик через туннель**, а не только скорость трубы. Это и есть ответ на «пингуется, но не работает».

## Требования

- `curl` — обязателен (есть в macOS и почти любом Linux из коробки).
- `unzip` — чтобы `node-check.sh` подтянул `xray` для туннельной проверки (`apt install unzip` / `brew install unzip`).
- `mtr` — по желанию, для среза маршрута (иначе `traceroute`).
- `node-check.sh` сам качает `xray-core` под платформу с официальных релизов [XTLS/Xray-core](https://github.com/XTLS/Xray-core) и кэширует в `~/.nodetest32`.

Поддержка протоколов в v1: `vless` и `trojan` (Reality / TLS / none, транспорты tcp/ws/xhttp/grpc/httpupgrade). `ss` / `vmess` / `hysteria2` туннелем пока не проверяются.
